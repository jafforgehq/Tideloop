# Tideloop 0.0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The owner chose continuous execution and asked not to stop for review.

**Goal:** Ship a signed, notarized, self-updating macOS planner built on mock A, with themes, MCP access, CI/CD and a public page.

**Architecture:** Main process owns state through a pure reducer in `src/shared`, persists it atomically, and pushes it to the renderer and MCP clients. The renderer dispatches actions over IPC. Every rule lives in `src/shared` or Electron-free `src/main` modules, so it is testable without a window.

**Tech Stack:** Electron 45, electron-vite 6, React 19, TypeScript, Vitest, Playwright, electron-builder 26, electron-updater 6, @modelcontextprotocol/sdk, zod.

**Spec:** `docs/superpowers/specs/2026-11-02-tideloop-design.md`

## Global Constraints

- App version `0.0.1`, bundle ID `com.jafforgehq.tideloop`, product name `Tideloop`, Developer ID team `R9QFVTDHY5`.
- Public repo `jafforgehq/tideloop-app`, MCP port `47613`, data file `planner.json` in `userData`.
- `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, a CSP with no remote origins, and no remote fonts or scripts.
- Text contrast at least 4.5:1 in every theme.
- Comments and docs in plain English. No secret values in the repo, logs or chat.

## Review Focus

- A corrupt or newer-version `planner.json`: never overwritten, owner is told. Test in Task 2.
- A date on a DST change or at a year boundary: week and month grids stay right. Test in Task 1.
- Quitting right after an edit: the last edit is on disk. Test in Task 2.
- An MCP call with a bad id, empty title or impossible date: a clean tool error, state unchanged. Test in Task 6.
- A web page calling the MCP port from a browser: refused. Test in Task 6.
